# 界面中文词条

`zh.tsv` 是桌面端所有界面文字的英文原文与中文对照，一行一条：

```
English string<TAB>中文
```

- 英文原文必须与界面代码里的字符串**完全一致**，包括大小写、空格和标点；对不上就原样显示英文。
- `#` 开头的行是注释，空行忽略。
- 表里没有的词条不会报错，也不会让界面出问题，只会以英文显示——上游新增的文字默认就是这个结果。

## 为什么放在代码外面

界面文字统一在 `desktop/src/look.rs` 的绘制函数里翻译（`crate::i18n::say`），消息对话框在
`desktop/src/files.rs` 里翻译。也就是说，词条只在**绘制时**查表，上游代码里的字符串、比较和
标识符都不改动，所以跟进上游时 `zh.tsv` 不会产生冲突：上游加了新句子的界面照常显示英文，
补一行中文就完成了本地化。

## 增加词条

1. 在界面上看到英文，去 `desktop/src` 里找到这句原文（通常直接搜字符串）。
2. 在 `zh.tsv` 对应分区里加一行，英文照抄，Tab 之后写中文。
3. 数字会变的消息用 `%` 占位，例如 `Delete % artworks?`，代码用 `crate::i18n::counted` 取它。
4. 重新编译即可生效，不需要改任何代码。

## 已知的边界

- 画作名、图层名、笔刷名这类**用户数据**不翻译：它们走的是 `one_line` / `galley` 之类的截断排版函数，
  没有接入查表，避免用户起的名字被误译。
- 系统文件选择框的标题（另存、导入）由系统绘制，只有部分位置接了词条。
- 安卓端的界面文字不走这套表（Kotlin/Compose 没有等价的绘制入口），仍是英文为主。
